# Household Expense Tracker

A self-hosted web app for tracking, categorising and visualising household spending. React, TypeScript, Tailwind CSS and Recharts in front; a small dependency-free Node server behind it.

**Your data is a folder of plain CSV files on the server.** The app reads and writes them through the server, every device sees changes live, and anything that can edit a CSV (a script, a spreadsheet, an AI agent) can work on them too, directly or through a small JSON API.

It's designed to run on a home server behind [Tailscale](https://tailscale.com/): `tailscale serve` provides HTTPS and tells the server who each request is from, so there are no accounts or logins.

## The data folder

| File | Contents |
|---|---|
| `transactions.csv` | `ID,Date,Description,Amount,CategoryId,Account,Notes,OriginalAmount,FxRate` |
| `categories.csv` | `Id,ParentId,Name,Path,OneOff,Archived,Color,Budget,Notes,CreatedAt` — the category tree |
| `rules.csv` | `Pattern,IsRegex,CategoryId,Enabled,CreatedAt` — auto-categorisation, first match wins |
| `import-profiles.json` | saved bank CSV column mappings |
| `activity.jsonl` | who changed what, when |
| `backups/` | snapshots of the four data files |
| `README.md` | schema and API documentation, written for AI agents (regenerated by the server) |

Conventions: dates ISO `yyyy-mm-dd`; amounts in AUD, positive = expense, negative = income/refund; `ID`/`Id` values never change; Unix `\n` line endings.

## The model

Money is broken down into one category tree, so every chart partitions cleanly:

- **Top-level categories** are the chart buckets ("where did my money go?"): Groceries, Home, Travel…
- **Sub-categories** nest to any depth; a transaction can be filed on any node, and reports roll descendants up into ancestors.
- **One-off cost centres** ("projects": a trip, a renovation, a baby) are nodes flagged `OneOff`, with optional budget and colour. They cluster at the end of pickers and can be hidden from trend analysis. **Archive** one when it's over: it drops out of pickers and suggestions, its rules are disabled, history stays.

Every transaction has exactly one category. Nothing double counts.

## Features

### Track & edit
- **Transactions**: filter by search / category / account / date range, sort, multi-select, bulk categorise and delete, inline editing, manual entry, split one transaction into several categories
- **CSV import**: drop any bank export; columns, date format (DMY/MDY/ISO) and sign conventions are detected. Mappings save as bank profiles that apply automatically to matching files. Duplicates (same date + amount + description) are skipped, foreign-currency files convert at a per-import rate, and a whole import can be filed into one category (e.g. a travel card into a trip)
- **Categories**: drag-and-drop tree management, rename / merge / move / archive, live counts
- **Rules**: "description contains X → category", applied on import or on demand, with suggestions mined from the uncategorised pile and from history, conflict and overlap inspection

### Analyse
- **Dashboard**: KPIs, monthly trend, category doughnut, top categories, cumulative spend, one-off budgets
- **Categories / Monthly / Trends**: drill-down pages with cross-navigation
- **Compare**: any two periods side by side, year-over-year presets, delta table, calendar heatmaps
- **Time scope**: all time, a year, or a custom range

### Shared and safe
- **Live**: changes from any device, person or agent appear everywhere within a second, with a note saying who made them
- **No lost edits**: every write names the revision it was based on; if someone else wrote first, the app replays its edit onto their version instead of overwriting it
- **Activity log**: every change with who made it, including direct file edits; changes made through the API can be undone with one click
- **Snapshots**: before each day's first change, before imports / uploads / restores, and before applying a direct file edit; kept 30 days, then monthly. Restore from the Data page
- **Downloads**: transactions CSV, full JSON backup; restore a JSON backup or upload a data folder from the old folder-based version
- **Works on phones** and installs to the home screen

## API

JSON over HTTP at `<base>/api`. Reads: `GET /summary`, `/categories`, `/transactions?uncategorized=1&q=…`, `/rules`, `/suggestions`, `/activity`, `/files/<name>`. Changes: `POST /import` (a bank CSV, same pipeline as the app's dialog; `dryRun` first), `/transactions/categorize`, `/categories`, `/rules`, `/rules/apply`, `/transactions`. The server writes the full reference into the data folder's `README.md`.

Identity: requests through `tailscale serve` are attributed to the Tailscale user; requests reaching the port directly (from the server itself) are local agents and can name themselves with an `X-Actor` header. `ALLOWED_LOGINS` (comma-separated, default `*`) limits which tailnet users get in.

## Running it

```bash
docker compose up -d --build     # serves http://127.0.0.1:8098/expense-tracker/, data in ./data
```

Then put it on the tailnet, e.g. `tailscale serve --bg --set-path=/expense-tracker http://127.0.0.1:8098/expense-tracker`.

## Development

```bash
pnpm install
pnpm dev:server    # API + data on :8098 (DATA_DIR defaults to ./data — use a scratch folder)
pnpm dev           # Vite on :3000, proxies /expense-tracker/api to the server
pnpm test          # vitest
pnpm build         # type-check app and server, build both (dist/, server/dist/main.mjs)
```
